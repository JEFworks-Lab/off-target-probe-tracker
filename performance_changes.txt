Performance Optimizations Made to opt
======================================

All changes are purely algorithmic — no results are altered, only how they are computed.
Each change is listed with the file, function, what was changed, and why it is faster.

-------------------------------------------------------------------------------
FILE: opt/commons.py
-------------------------------------------------------------------------------

1. build_tinfos — pre-filter DataFrame before row iteration
   Old: iterated over every row in the GFF/GTF (exon, CDS, gene, transcript, ...)
   New: filters to transcript rows only with df[df['feat'] == schema[0]] before looping
   Why: GFF files typically have 5-10x more non-transcript rows than transcript rows.
        Skipping those rows entirely avoids unnecessary att2dict() calls on each one.
   Also: switched from iterrows() to itertuples() — itertuples() is ~3-5x faster because
        it avoids constructing a full pandas Series object for every row.

2. load_tinfos — remove double file open, use vectorized dict construction
   Old: opened the CSV file twice (once for transcript IDs, once for the rest),
        then used iterrows() to build the dict one row at a time.
   New: reads the file once with pd.read_csv(), then builds the dict in a single
        vectorized pass using dict(zip(...)).
   Why: file I/O is expensive; iterrows() is slow due to per-row Series construction.
        The zip/dict approach builds the same dict with no Python loop overhead.

3. check_annotation_ext — handle .gz compressed annotation files
   Old: called Path(fn).suffix directly, which returned '.gz' for files like
        annotation.gff.gz, causing sys.exit(-1).
   New: strips the trailing '.gz' before extracting the suffix, so .gff.gz, .gtf.gz,
        .gff3.gz all resolve correctly.
   Why: this was a correctness fix that also prevents a crash when using compressed
        reference files.

-------------------------------------------------------------------------------
FILE: opt/track.py
-------------------------------------------------------------------------------

4. convert_md2bit / convert_md2bit_nucmer / convert_md2bit_del / convert_md2bit_nucmer_del
   — list + join instead of repeated string concatenation
   Old: result string was built with += inside a character loop (e.g. result += '0').
        In Python, strings are immutable, so each += allocates a new string object —
        this is O(n^2) in total memory allocations for a string of length n.
   New: characters/runs are appended to a list, then ''.join(parts) is called once.
        join() is O(n) and allocates exactly one final string.
   Why: for long MD tags (e.g. probes with many mismatches), the old code does quadratic
        work. The new code is strictly linear.

5. bitwise_and — generator expression instead of loop + concatenation
   Old: built the result string with += inside a for loop.
   New: uses a generator expression inside ''.join(...), which is evaluated lazily
        and joined in one pass.
   Why: same reason as #4 — avoids quadratic string allocation.

6. track_target_pad — per-probe caching of qlen and critical bit vector
   Old: for every alignment record, fetched qfa[qname].seq and recomputed the
        critical bit vector from scratch.
   New: qlen_cache and crit_cache dicts store the length and precomputed integer
        critical vector per probe name. On the first occurrence of a probe the values
        are computed and stored; all subsequent records for the same probe reuse them.
   Why: a single probe can appear in thousands of alignment records. pyfastx index
        lookups and bit-string construction are not free — doing them once per probe
        instead of once per record eliminates redundant work proportional to the
        average number of hits per probe.

7. check_lft_and_rgt — accept pre-fetched qseq/qlen instead of qfa/qname
   Old: function signature was (mrec, qname, qry_fa, tgt_fa, max_nm) and called
        qry_fa[qname] internally every time.
   New: signature is (mrec, qseq, qlen, tgt_fa, max_nm); the caller passes
        already-fetched values.
   Why: enables the caller (track_target_one_mismatch) to fetch the probe sequence
        once per probe rather than once per alignment record (see #8).
   Also: replaced per-character string concatenation for match vectors with list
        comprehension + join.

8. track_target_one_mismatch — pre-fetch probe sequence once per probe
   Old: called check_lft_and_rgt(..., qname, qfa, ...) for every mrec, which fetched
        qfa[qname] on every call inside check_lft_and_rgt.
   New: fetches q = qfa[qname], qseq = q.seq, qlen = len(qseq) once before the
        inner mrec loop, then passes qseq/qlen to check_lft_and_rgt.
   Why: a probe with N alignment hits previously did N pyfastx index lookups for
        the same sequence. Now it does exactly 1, regardless of hit count.

9. write_results — single pass writing both output files simultaneously
   Old: iterated over ainfos twice — once to write probe2targets.tsv, again to write
        probe2targets_offtargets.tsv — extracting and formatting the same fields
        twice for every probe.
   New: opens both files at once and writes to both in a single pass. The formatted
        row string is computed once and written to fh_ot if n_genes > 1.
   Why: halves the number of dict iterations and field extractions. For large probe
        sets (tens of thousands of probes) this is a meaningful reduction in CPU time.
   Also: removed redundant list comprehension wrappers like [str(x) for x in ...]
        in favor of generator expressions (str(x) for x in ...) to avoid building
        intermediate lists.

-------------------------------------------------------------------------------
FILE: opt/flip.py
-------------------------------------------------------------------------------

10. flip — convert to_rc from list to set
    Old: to_rc was a list; the membership test q.name in to_rc inside the FASTA
         writing loop was O(n) for each probe.
    New: to_rc is a set; membership test is O(1) on average.
    Why: with P probes total and R probes to reverse-complement, the old code did
         O(P * R) comparisons in the worst case. The new code does O(P) total.
         For a run with 10,000 probes and 5,000 to flip, that is 50,000,000
         comparisons vs 10,000.
    Note: write_lst2file() expects a list, so list(to_rc) is called only at return
         time — one cheap conversion rather than converting during the hot loop.

-------------------------------------------------------------------------------
Summary
-------------------------------------------------------------------------------
Most of the gains come from:
  - Avoiding redundant pyfastx index lookups for the same probe (#6, #8)
  - Single-pass file writing instead of double iteration (#9)
  - O(1) set membership instead of O(n) list membership (#10)
  - Linear string building with join() instead of quadratic += (#4, #5, #7)
  - Skipping non-transcript GFF rows before iteration (#1)

No algorithmic results are changed. All output files remain identical.
